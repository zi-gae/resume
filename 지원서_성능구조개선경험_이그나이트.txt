이그나이트에서 글로벌 딜러 포탈을 개발하면서 크게 두 가지 문제를 개선한 경험이 있습니다.

**MSA 환경의 인증 구조 문제**

현대·기아·제네시스 포탈은 MSA 구조로 각 도메인이 서로 다른 인증 방식과 요청 헤더를 사용했습니다. 초기에는 도메인별로 클라이언트를 개별 구현했는데, A 서비스 토큰이 갱신되는 도중 B 서비스 요청이 동시에 들어오면 인증 실패가 연쇄적으로 발생하는 문제가 있었습니다.

핵심 원인은 토큰 갱신 타이밍이었습니다. A 토큰이 만료되면 B 토큰도 연쇄 무효화되는데, 여러 요청이 동시에 갱신을 시도하면서 중복 요청이 터졌습니다. Mutex 패턴으로 갱신 요청을 단일화하고, 갱신 중 들어오는 요청은 큐에 담아 완료 후 순차 재시도하는 구조로 바꿨습니다. 결과적으로 동시 요청 최대 50건을 안정적으로 처리하게 됐고, Datadog 기준 인증 성공률이 99.7%까지 올라왔습니다.

**SonarQube 이슈 처리 자동화**

프로젝트 규모가 커지면서 CRITICAL/BLOCKER 이슈가 매 스프린트마다 누적되기 시작했습니다. 이슈 확인 → JIRA 티켓 생성 → 코드 수정 → MR 생성까지 전부 수작업이라 스프린트당 약 6SP가 반복 작업에 사라지고 있었습니다.

Claude Code CLI를 비대화형 모드로 활용하고 GitLab CI/CD에 연동해, 매일 07시에 자동으로 이슈를 수집하고 파일 단위로 묶어 병렬 처리하는 파이프라인을 만들었습니다. 초기에는 AI가 관련 없는 코드까지 건드리는 문제가 있었는데, 허용 파일 목록을 명시하고 리팩토링·스타일 변경을 금지하는 프롬프트 제약을 추가해서 해결했습니다.

이후 이슈 발견부터 MR 생성까지 4단계가 전부 자동화됐고, 스프린트 투입 공수가 6SP에서 코드 리뷰 0.5SP 수준으로 줄었습니다.
