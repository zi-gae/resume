[필수] 서비스 개발 또는 운영 과정에서 발생한 성능 문제, 구조적 문제, 또는 반복적인 개발 작업을 개선한 경험이 있다면 설명해 주세요.

---

세 가지 유형의 문제를 개선한 경험을 소개합니다.

■ 성능 문제: 캘린더 컴포넌트 리렌더링 (마이리얼트립 Staynet)

숙박 예약 캘린더에서 셀 하나를 변경할 때 전체 테이블이 리렌더링되는 문제가 발생했습니다(Performance 탭 측정 800ms+). React Profiler로 분석하니 table 구조 특성상 DOM 변경이 전체 행에 전파되고 있었습니다. div 기반 가상화 구조로 전환하고 React.memo로 row 단위 격리 렌더링을 적용해 120ms로 개선했습니다(85% 절감). 함께 발견된 입력 필드 30개+의 실시간 렌더링 성능 저하도 ContextAPI + Ref 기반 비제어 컴포넌트 패턴으로 전환해 렌더링 횟수 90% 감소시켰습니다.

■ 구조적 문제: Turborepo 원격 캐시 히트율 저하 (이그나이트)

원격 캐시 도입 후 히트율이 30%대에 머물러 빌드 시간 개선 효과가 미미했습니다. 빌드 출력 로그를 분석하니 lock 파일이 변경될 때마다 전체 패키지 캐시가 일괄 무효화되는 구조가 원인이었습니다. 패키지 단위 캐시 전략으로 변경해 히트율 85% 달성, 평균 빌드 시간 4분 → 1.5분으로 단축했습니다.

■ 반복 작업: CI 병목 제거 (마이리얼트립 TF)

공통 모듈 CI에서 Lint + Jest가 12분 이상 소요돼 개발 흐름이 끊기는 문제가 있었습니다. Actions workflow 로그를 분석하니 Barrel 파일 간 순환 참조로 모듈 해석 인스턴스가 무한 생성되는 것이 원인이었습니다. Barrel 파일을 제거하고 직접 import로 전환해 빌드/테스트 시간을 12분 → 5분으로 단축했습니다.

세 사례 모두 추측이 아닌 측정 → 원인 파악 → 개선 검증 순서로 접근한 것이 핵심이었습니다.
